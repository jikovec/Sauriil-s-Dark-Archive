## Source baseline used

The skeleton was created from these uploaded source documents and the explicit user scope:

```txt
Dark Archive Cross-Platform Ic.md
Dark Archive theme build handoff.md
```

The cross-platform plan established:

- Windows 11 native-first icon customization.
- Windows registry-backed customization only after backup/export.
- Third-party Windows tool risk ordering.
- Arch Linux/KDE Plasma as the primary Linux target.
- Per-user XDG icon theme install under `~/.local/share/icons`.
- `breeze,hicolor` inheritance.
- `.desktop` overrides only under `~/.local/share/applications`.
- Non-destructive dry-run-first tooling.
- `48x48` readability as the identity proof size.
- Windows multi-size `.ico` output expectations.
- Linux SVG + PNG fallback expectations.

The WinRAR handoff established the visual and practical precedent:

- Theme identity: `Sauriil Dark Archive`.
- Dominant style: black forged steel, ash parchment, blood-red ritual seals, subtle cyan glow, restrained pale-gold filigree, occult circular geometry.
- Rendering direction: semi-realistic premium dark fantasy, not generic neon gamer, not cartoon.
- Protected-symbol rule: no copied Elder Scrolls, Dark Brotherhood, Aldmeri, Microsoft, KDE, GNOME, Arch, WinRAR, or other official/protected symbols.
- Practical size lesson: `128x128` toolbar icons were too large; `48x48` was the best working readability/richness balance.
- Root/app/archive icons should become multi-size `.ico` files when real assets exist.

## v0.0.1 task scope

The requested task was to create the first non-destructive repository skeleton package.

It was explicitly **not**:

- an icon-art generation task,
- a visual sample-icon generation task,
- a live system customization task,
- a Windows registry modification task,
- a Linux system-wide install task,
- permission to patch Windows system files,
- permission to use 7TSP,
- permission to modify `/usr/share/icons`,
- permission to modify `/usr/share/applications`,
- permission to create fake finished icons,
- permission to claim that the theme is installed,
- permission to overclaim OS-wide icon control.

Core skeleton-only rule followed:

- No PNG, SVG, ICO, CUR, or image placeholder icons were created.
- No sample dark-fantasy icons were generated.
- No visual test icons were generated.
- Empty icon directories contain only `.gitkeep` files.
- Mapping CSVs contain only safe example rows marked as `example`.
- Example rows point to missing/future expected asset names and are reported as known gaps.
- The package is clearly labeled as a skeleton, not as a completed usable icon theme.

## First real icon batch recommended

The next real phase should not immediately attempt whole-OS coverage.

Recommended first real icon batch:

```txt
apps:
  sauriil-terminal
  sauriil-browser
  sauriil-code-editor
  sauriil-file-manager

places:
  folder
  folder-documents
  folder-downloads
  user-home

mimetypes:
  application-zip
  application-x-rar
  text-x-script
  text-x-python
```

Reasoning:

- small enough to validate safely,
- covers visible daily-use surfaces,
- proves Windows `.ico` conversion,
- proves Linux scalable/fallback placement,
- proves 48x48 readability,
- avoids risky Windows shell/resource modifications,
- avoids pretending to provide full OS-wide icon control.

Existing WinRAR assets may be used as visual reference/source material, but WinRAR toolbar commands like `Add.png` or `Extract.png` should not be blindly reused as OS app icons.
